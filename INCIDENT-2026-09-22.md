# 2026-09-22 homepage incident

## User-visible failure

- With `homePath: "homepage.md"`, `openOnStartup`, `forcePreview`, and `hideTitle`
  enabled, the homepage rendered blank.
- Other Markdown files could no longer be opened normally.
- Disabling the homepage group or disabling Paper Desk restored the vault.

## Runtime evidence

The Obsidian 1.13.7 developer console repeatedly reported:

```text
TypeError: e.show is not a function
TypeError: this.currentMode.onResize is not a function
TypeError: this.currentMode.getEphemeralState is not a function
```

The Obsidian 1.13.7 application code shows that `MarkdownView.setMode()` accepts an
internal Mode object. It calls `e.show()`, `e.onResize()`, and other Mode methods after
assigning `this.currentMode = e`. It does not accept the string `"preview"`.

Paper Desk called:

```js
view.setMode("preview");
```

That assigned a string to `currentMode`. The next resize, history-state save, or file-open
operation then failed inside Obsidian itself. This one API misuse explains both the blank
homepage and the inability to open other notes.

## Why the first attempted fix was insufficient

The first fix kept the re-entry guard alive until the asynchronous mode change completed.
That guard was useful but not causal: it still invoked the wrong API, so it only protected
an operation that corrupted the Markdown view.

The render test also reproduced a false reality. Its `view.setMode("preview")` stub accepted
a string and changed a local variable, whereas real Obsidian expects a Mode object. The stub
therefore certified the dangerous call instead of rejecting it.

## Repair

- Never call `MarkdownView.setMode()` with a string.
- Read the leaf state with `leaf.getViewState()`.
- Copy the state, set `state.mode = "preview"`, and apply it with
  `leaf.setViewState(nextState)`—the same state transition used by Obsidian's own mode toggle.
- Keep the asynchronous re-entry guard until `leaf.setViewState()` settles.
- Register all three Markdown code-block processors before fallible initialization steps.

## Regression coverage

`tests/render.test.js` now models a real `WorkspaceLeaf`:

- `MarkdownView.setMode()` throws if the plugin calls it with a string.
- `WorkspaceLeaf.getViewState()` / `setViewState()` perform the mode transition.
- A second `file-open` during the pending transition cannot start another transition.
- A later, separate arrival at the homepage can start a new transition.
- The three homepage processors remain registered if later `onload()` work fails.

The corrected test was observed failing against the old implementation at the dangerous
`view.setMode("preview")` call, then passing after the production repair.

## Safe recovery sequence

1. Fully exit Obsidian so the corrupted in-memory `currentMode` objects are discarded.
2. Temporarily clear `homePath` and turn off the homepage switches in the vault's
   `data.json`.
3. Synchronize the repaired plugin files.
4. Start Obsidian and verify ordinary notes open normally.
5. Fully exit Obsidian again, restore the homepage settings, then test the homepage in a
   fresh process.

At the time this record was written, step 4 had passed in the real vault. The homepage
switches were still intentionally off; homepage re-enablement remained to be verified.
